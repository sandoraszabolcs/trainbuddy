## Known issues / next actions

1. **Persona text contradicts derived stats.** `fallback_card()` prints the archetype's
   sampled distance ("Typical session 28 km") while the athlete's actual activities come
   from the route pool, so `typical_distance_m` says 10.2 km. Fix: build the card *after*
   activities exist, from the derived values. `app/seed/personas.py` + `generate_athletes.py`.
2. **Access-log request id is `-`.** The contextvar is reset before uvicorn's access
   logger runs. Fix: emit our own access line inside the middleware in `app/main.py`.
3. **Route pool is currently synthetic.** `route_pool.json` was built with
   `--synthetic 47.4979,19.0402` (dev fallback: mathematical loops, visibly fake on a
   map). Once Strava OAuth + sync work, rebuild it with plain `python -m app.seed.route_pool`
   so seeded routes follow real streets.
4. **No Strava app credentials yet.** `.env` holds an old `STRAVA_ACCESS_TOKEN` from the
   November spike (expired — Strava access tokens last 6 hours). Need `STRAVA_CLIENT_ID`
   and `STRAVA_CLIENT_SECRET` from https://www.strava.com/settings/api, plus the
   self-service upgrade to 10 athletes if a second person should ever connect.
5. **Alembic + GeoAlchemy2 gotcha (already handled, don't undo).** GeoAlchemy2 creates
   spatial indexes itself during `create_table`; autogenerated `op.create_index('idx_...')`
   lines duplicate them and fail with `DuplicateTable`. They were deleted from the
   migration. `alembic/env.py` also filters autogenerate down to tables in our metadata,
   otherwise it proposes dropping every PostGIS tiger-geocoder table.
6. **`.cast(text("geography"))` does not work** in SQLAlchemy 2 — use GeoAlchemy2's
   `Geography(...)` / `Geometry` types. Cost an hour; see `app/matching.py`.
